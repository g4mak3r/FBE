# FBE 0.85 - установка, профили и рабочие данные

## Запуск

Распакуйте FBE в отдельную папку, выполните `install_fbe.bat`, затем используйте созданный ярлык или `start_fbe.bat`.

Без подключения FBE открывает пустой REAL workspace. Нажмите **«Подключить Wildberries»** в sidebar и введите API token. Токен проверяется read-only запросом профиля продавца; seller SID берется из подтвержденного ответа WB. После изменения профиля или REAL / DEMO режима локальный сервер перезапускается через `start_fbe.bat`.

Если FBE запускается напрямую через Uvicorn, процесс после изменения профиля может завершиться с кодом `75`; в таком случае запустите его повторно вручную.

FBE рассчитан на один локальный процесс без `--workers` и `--reload` и слушает `127.0.0.1`.

## Seller SID и рабочие пространства

Для каждого продавца используется отдельный workspace:

```text
data/workspaces/<SHA-256 UTF-8 seller SID>/
```

Хеш используется только как безопасное имя каталога. Внутри workspace находятся:

- `fbe.db`;
- кеши;
- экономика и выгрузки;
- PDF/стикеры/QR;
- логи;
- локальные BarTender-шаблоны;
- seller-scoped runtime state.

`data/unconnected/` используется до подключения и после отключения профиля.

При смене аккаунта новый токен не применяется к уже работающему процессу: FBE сохраняет профиль, блокирует новые рабочие действия до restart и только новый процесс выбирает новый token, SID, настройки ЧЗ и пути.

Повторное подключение того же SID открывает прежний workspace. FBE не удаляет seller workspace автоматически.

## Credentials

Локальное хранилище:

```text
data/local/connections.json
```

Оно содержит текущий WB token, подтвержденный профиль, выбранный режим и настройки ЧЗ по seller SID. Запись выполняется атомарно.

На Windows это локальный JSON под правами пользователя текущей папки; встроенного DPAPI/шифрования в 0.85 нет. Поэтому:

- не публикуйте runtime-папку;
- не отправляйте `connections.json` третьим лицам;
- не храните FBE в общей сетевой папке с чужим доступом.

Токен не возвращается UI/API и не подставляется обратно в форму.

Старые `WB_TOKEN`, `FBE_WB_TOKEN`, `CZ_*`, токены экономики и credentials из legacy `config.json` автоматически не активируются, если они не имеют надежной привязки к seller SID.

`config.json` остается локальным файлом несекретных настроек оборудования. `FBE_DRY_RUN_PRINT` может использоваться в REAL; DEMO всегда принудительно включает dry-run.

## Настройки Честного Знака

Настройки True API / СУЗ сохраняются отдельно для seller SID через общий профиль подключения. В них могут входить:

- ИНН;
- OMS ID;
- Connection ID;
- thumbprint сертификата;
- параметры товарных групп/документов.

При переносе legacy-установки задайте их заново после подключения правильного WB seller.

## Перенос legacy SQLite

FBE 0.85 не использует старую `data/fbe.db` автоматически: без подтвержденного seller SID невозможно надежно определить ее владельца.

1. Остановите старый и новый FBE.
2. Сделайте резервную копию всей старой установки.
3. Определите seller SID владельца БД по подтвержденному профилю WB. Если SID неизвестен - не переносите базу.
4. Из папки FBE 0.85 выполните:

```text
.venv\Scripts\python.exe tools\adopt_legacy_workspace.py --source "C:\OLD_FBE\data\fbe.db" --sid "SELLER_SID"
```

5. Инструмент проверяет SQLite и создает snapshot через SQLite backup API. Исходная БД не удаляется и не заменяется.
6. Уже существующий seller workspace не перезаписывается. Если до миграции был создан пустой workspace, остановите FBE, сохраните его отдельно и только после этого повторите перенос.
7. Запустите FBE и подключите того же продавца через профиль.

Не объединяйте SQLite разных seller SID вручную.

Legacy XLSX остатков, настройки экономики и кеши автоматически не импортируются: их принадлежность конкретному продавцу требует ручной проверки. Для каталога остается штатный импорт.

## BarTender-шаблоны

Рабочие `.btw` не входят в публичный source-кандидат: такие бинарные файлы могут содержать встроенные данные, локальные пути и идентификаторы.

### Автоматический безопасный перенос при обновлении

При запуске `install_fbe.bat` из новой папки FBE до создания нового ярлыка проверяет старый ярлык `FBE.lnk`. Если предыдущая установка доступна и в ней найдены поддерживаемые шаблоны (`default.btw`, `perfume.btw`, `spa.btw`, `set.btw`, `samples.btw`, `names.btw`), установщик спрашивает, сохранить ли их для переноса.

После подтверждения файлы копируются только в локальный staging:

```text
data/local/template_import/pending/
```

Этот каталог исключен из Git. База данных, токены и credentials при этом автоматически не переносятся.

После подключения Wildberries FBE показывает предложение **«Перенести шаблоны в этот профиль»**. Только после явного подтверждения `.btw` копируются в:

```text
data/workspaces/<seller-hash>/templates/
```

Правила безопасности:

- существующие seller-local `.btw` никогда не перезаписываются;
- если staging был получен из seller-scoped workspace предыдущей 0.85-установки, он привязывается к тому же seller SID и не импортируется в другой профиль;
- legacy `templates/*.btw`, где SID исторически неизвестен, пользователь сам привязывает к текущему подтвержденному профилю;
- DEMO не видит и не импортирует реальные шаблоны;
- исходная предыдущая установка не изменяется.

Если старый ярлык не найден или автоматический staging был пропущен, остается ручной способ:

```text
.venv\Scripts\python.exe tools\import_local_templates.py --from "C:\OLD_FBE\templates" --sid "SELLER_SID"
```

После импорта проверьте в BarTender источники CSV и принтеры. Физическая печать зависит от локальной Windows-конфигурации и не может считаться проверенной только regression-тестами.

## DEMO MODE

DEMO использует отдельную синтетическую БД с фиктивными товарами, поставками, заданиями, КИЗ и экономикой.

В DEMO:

- реальный `config.json`, inventory и seller credentials не используются;
- WB отвечает локальным mock;
- True API / СУЗ блокируются;
- process-level safety guard блокирует исходящую сеть и внешние процессы;
- Windows RAW/GDI print paths блокируются;
- dry-run нельзя отключить настройкой или environment variable;
- Java/BarTender/PowerShell production-действия недоступны.

Часть сложных print-preview операций в DEMO может завершаться безопасной ошибкой вместо создания настоящего PDF/запуска внешнего процесса.

При выходе из DEMO FBE возвращается к предыдущему REAL seller после restart.

## Release checks

```bash
python -m pytest -q
python -m compileall -q .
python tools/check_workspace.py
python tools/git_safety_check.py .
```

`git_safety_check.py` проверяет текущие файлы/индекс на типичные runtime secrets, SQLite families, сертификаты, opaque BarTender files и другие опасные артефакты. Он не очищает Git history и не является криптографической гарантией отсутствия любого возможного секрета.
