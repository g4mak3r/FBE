# Единый ассортимент: этап 7

Версия FBE Flow 0.7 добавляет самостоятельный блок «Ассортимент». Он хранит собственные
товарные варианты продавца, документы соответствия, партии и связи с НК, WB, Ozon и KIT.
Карточки источников сохраняют прежние UUID и собственные данные.

## Начало работы

1. Выберите продавца и откройте «Ассортимент».
2. Скачайте пустой шаблон FBE либо создайте товар в форме. Одна строка — один товарный
   вариант; размеры WB chrtID и SKU отправления Ozon связываются отдельно.
3. Для переноса существующих карточек сначала обновите товары в соответствующем модуле.
   В «Карточки площадок» проверьте поля варианта, создайте товар либо свяжите его с
   существующим. Совпадение GTIN отображается как подсказка, объединение не выполняется.
4. При необходимости прочитайте полные характеристики Ozon отдельной кнопкой.
   Обновляются сведения источника; собственная карточка сохраняется.
5. Добавьте декларацию, сертификат или СГР, даты и область применения. Один документ
   может применяться к нескольким товарам. Приложите PDF/PNG/JPEG и укажите основание,
   если документ проверен вручную.
6. Создайте партию, назначьте сохранённые коды нужного GTIN и фиксируйте печать,
   нанесение и проверку качества на конкретных экземплярах.
7. Настройте проверенное правило классификации с источником, датами и исключениями.
   Прочитайте ЧЗ и сравните ТН ВЭД, ОКПД2, GTIN, карточку НК и группы аккаунта.
8. Продолжайте работу с заказами и передачей кодов в «Маркетплейсы → WB/Ozon» либо
   в отдельном блоке интернет-магазина.

## Поля и идентичность

| Сведения | Хранение |
| --- | --- |
| Собственный товар | UUID, версия, артикул, наименование, семейство, бренд, производитель, страна |
| Описание | Состав, описание, объём в мл, срок годности в днях |
| Упаковка | Длина/ширина/высота в мм, нетто/брутто в г, количество единиц |
| Классификация | ТН ВЭД из 10 цифр, ОКПД2, ключ группы ЧЗ |
| Идентификаторы | GTIN с контрольной цифрой и ведущими нулями; отдельный список штрихкодов |
| Характеристики | Типизированные JSON-значения; идентификаторы характеристик источника сохраняются |
| Документ | Вид, номер, выдача/окончание, орган, область, ручная проверка и файлы |
| Применимость | Отдельная связь документа с каждым товаром |
| Партия | Товар, название, количество, производство/годность |
| Экземпляр | Связь партии с сохранённым кодом ЧЗ и событиями оператора |
| Источник | UUID карточки, конкретный вариант, данные и идентификаторы площадки |

GTIN-8/12/13/14 нормализуется в текст GTIN-14 с проверкой контрольной цифры.
Артикул и GTIN уникальны внутри продавца. Совпадения между продавцами не раскрываются.
Обычный штрихкод без действительной контрольной цифры не становится GTIN автоматически.

Поля собственных товаров обновляются с проверкой версии. Повторное сохранение одинаковых
данных не создаёт новую версию. Архив доступен отдельно; удаление строки Excel не удаляет
товар. Семейство объединяет варианты для обзора, не заменяет их отдельные идентичности.

## Обмен XLSX

В «Обмен XLSX» доступны пустой шаблон, полная выгрузка и выгрузка выбранных товаров.
Рабочие листы: «Товары», «Характеристики», «Документы», «Применимость», «Связи»,
«Партии», «Правила». Вторая строка содержит стабильные ключи и скрыта; данные начинаются
с третьей. При обновлении необходимо сохранить ID и версию.

Справочные листы показывают карточки площадок, метаданные файлов документов и статусы
маркировки. Изменения этих листов не меняют файлы, связи или внешние статусы.
Полные КМ и вложения документов не помещаются в XLSX. Они сохраняются в SQLite и её
резервной копии; прежний JSON-экспорт блока КМ доступен в модуле ЧЗ.

| Значение ячейки | Действие |
| --- | --- |
| Пусто | Сохранить прежнее значение; для нового товара — значение по умолчанию |
| #CLEAR | Очистить поле или удалить дополнительную характеристику |
| ##CLEAR | Сохранить буквальный текст #CLEAR |
| ID + актуальная версия | Обновить существующую запись |
| Новая строка без ID | Создать запись; совпадения артикула/GTIN требуют явного решения |
| Нет строки в файле | Сохранить запись в программе |
| «В архиве» = Да | Переместить товар в архив |
| «Связать с документом» = Нет | Убрать только эту применимость |

Идентификаторы должны быть текстом. Числовой GTIN/ТН ВЭД и формулы отклоняются с указанием
листа, строки и колонки: потерянные Excel цифры восстановить достоверно нельзя.
Текст, начинающийся с «=», выгружается как текст; входная формула не исполняется.

Предпросмотр показывает создания, обновления, значения «Было/Будет», предупреждения и
ошибки. База до применения не меняется. План хранится между перезапусками и применяется
один раз. Любая ошибка или изменение версии после предпросмотра отменяет всю транзакцию.
Из импорта не запускаются внешние команды, подписание документов или передача КМ.

Лимиты: XLSX до 32 МБ, до 100 000 строк данных на лист, 250 колонок и 5 млн ячеек.
Для большого числа дополнительных характеристик используйте выгрузку выбранной части.
Файлы документов: PDF/PNG/JPEG до 10 МБ каждый.
Полный снимок изменения общего документа хранится один раз; история каждого товара
содержит применимость и ссылку на этот снимок.

## Шаблоны WB и Ozon

Категории и колонки маркетплейсов различаются. Используйте шаблон нужной категории,
скачанный из своего кабинета. Flow читает листы и предлагает соответствия полей; их можно
изменить, сохранить неизвестную колонку в дополнительных характеристиках либо пропустить.
При пропуске заполненной колонки появляется предупреждение.

WB использует габариты в см и массу брутто в кг; собственная база хранит мм и г.
В сопоставлении явно показан множитель. При заполнении шаблона применяется обратный
перевод. Для Ozon учитываются явные единицы и характеристики конкретной категории.

Для заполнения предоставленного шаблона выберите товары, лист, строку заголовков и
первую строку данных. Flow заменяет область данных выбранного листа, сохраняет другие
листы, справочники, оформление и проверки значений. Полученный файл нужно проверить
в кабинете площадки: здесь не отправляются карточки и не обещается принятие любого
категорийного XLSX.

Живые справочники читаются по API:
- WB: subjectID, характеристики /content/v2/object/charcs/{subjectID} и справочник ТН ВЭД.
- Ozon: description_category_id:type_id, характеристики категории и страницы словаря.
- Ozon: /v4/product/info/attributes для полной исходной карточки.

Схемы сохраняются отдельно для подключения и категории. Они не заменяют проверку
площадкой актуального шаблона. Первичные источники:
[WB Content API](https://dev.wildberries.ru/openapi/work-with-products),
[Ozon Seller API](https://docs.ozon.ru/api/seller/).

## Сверка с ЧЗ

Правило содержит дату начала/окончания, приоритет, источник, префиксы ТН ВЭД/ОКПД2 и
условия по составу, объёму или дополнительным характеристикам. Результат: однозначное
соответствие, отсутствие правила, нехватка данных либо противоречие правил.
Нормативные правила не подменяются демонстрационными примерами.

Проверка читает собственный аккаунт, точный ТН ВЭД через True API v4 /tn-ved/search,
сведения о GTIN через /product/info и карточку НК через /v3/product. Сравниваются
подключённые группы, ожидаемая группа, ТН ВЭД, ОКПД2 и подтверждение карточки.
Группа из справочника не доказывает обязанность маркировки или освобождение от неё.

Расхождения показываются оператору. Кнопка вставки группы меняет форму; сохранение
товара остаётся отдельным действием. Данные НК, группы аккаунта и документы ЧЗ
автоматически не изменяются. Проверка устаревает после изменения товара, правил,
параметров подключения, даты либо по истечении 24 часов.

Источник API: [True API](https://markirovka.crpt.ru/api/v4/true-api).
Требования группы и исключения необходимо учитывать в проверенном правиле с источником.

## Маркировка и существующие операции

| Сведение | Что подтверждает |
| --- | --- |
| Заявление в карточке / kizMarked WB | Заявление для товарной карточки |
| Печать/нанесение/контроль качества | Локальное событие с оператором и временем |
| Статус кода и отчёта ЧЗ | Полученное внешнее состояние юридического оборота |
| Результат передачи WB/Ozon/KIT | Отдельное подтверждение соответствующего канала |

Назначение кода партии не заменяет резерв кода в заказе. Общий резерв физических КМ
между WB/Ozon/KIT сохранён. При наличии связи с ассортиментом существующие операции
проверяют активность товара, GTIN и группу; противоречие блокирует подготовку или отправку.
Старые связи без ассортиментной карточки продолжают работать.

Связь источника, уже используемая для ЧЗ, защищена от противоречивого изменения.
При назначенных экземплярах нельзя менять GTIN или группу товара. Внесение событий
оператора не переводит код в APPLIED/INTRODUCED и не создаёт отчёт СУЗ.

## Обновление и проверка

Migration 007 добавляет seller-scoped таблицы ассортимента, документов, файлов, партий,
экземпляров, событий, правил, схем категорий, сверок и планов импорта.
Миграции 001–006 не переписывались. Перед обновлением создаётся SQLite-копия
flow.before-v7.sqlite3. Старые UUID, очередь, журналы и резерв КМ сохраняются.

Автоматические проверки покрывают изоляцию, версии, параллельное редактирование, атомарность
импорта, ведущие нули, формулы, пустые ячейки, дополнительные характеристики, документы,
файлы, варианты WB, полные характеристики Ozon и чтение ЧЗ. Браузерный сценарий проверяет
формы, экземпляры, XLSX, схемы/словари, настольный и мобильный экраны.
В CI проверки Python выполняются на Linux 3.11 и Windows 3.12, параллельно — браузерный
сценарий Chromium. Снимки настольного и мобильного интерфейса сохраняются в артефактах
сборки на семь дней.

Из каталога fbe-flow:
- python -m pytest
- python -m ruff check .
- python -m ruff format --check .
- npm --prefix qa ci --ignore-scripts
- cd qa && npx playwright install chromium
- из fbe-flow: node qa/catalog_browser.cjs
- python -m qa.catalog_benchmark --count 30000

Браузерные и нагрузочные проверки используют временную БД и ответы протокольных двойников.
Промышленная приёмка конкретных XLSX и обмена с действующими кабинетом/УКЭП выполняется
с файлами и доступом пользователя; она не подменяется результатами изолированных тестов.
