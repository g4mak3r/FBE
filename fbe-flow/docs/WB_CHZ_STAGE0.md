В начале аудита было 24 измененных/новых файла. Они сохранены без дальнейшего

## Что есть в коде

«Реализовано» ниже означает наличие реализации, а не проверку реального кабинета.

| Функция | Состояние | Что нужно закончить / проверить |
| --- | --- | --- |
| Подключение WB, синхронизация заказов, карточек, складов и поставок | Реализовано | Этап 1: сверить полноту и статусы с реальным кабинетом, восстановление после ошибки чтения |
| Фото, карточки заказов, фильтры, массовый выбор | Частично | Новый интерфейс еще без браузерной приемки. Фото берется из данных карточки, разрешены CDN WB; нужна проверка вариантов, отсутствующего фото и соответствия заказа |
| Создание, наполнение, перенос и просмотр поставок | Частично | Журнал команд и проверки совместимости есть. Новый быстрый сценарий не принят; шаблон имени не настраивается, технический суффикс еще остается в имени на стороне WB |
| Ассортимент, связи, партии и документы | Реализовано | Проверить реальные связи вариантов WB и заполненность партий; миграция не заполняет бизнес-данные автоматически |
| Массовая передача сроков годности | Частично | Добавлены даты из партий, очередь и сверка WB. Нет отдельной приемки нового пути; расчет из производства/срока хранения и обработка всех проблемных случаев требуют этапа 3 |
| НК, заказ/получение КМ в СУЗ, документы ЧЗ | Частично | Основные операции и журнал существуют, часть документов вводится через JSON. Нужно пройти цепочку для конкретной подключенной группы; не считать юридический путь универсально завершенным |
| Ручное закрепление и передача полных КМ в WB | Реализовано | Существуют проверки GTIN/группы, владельца и статуса ЧЗ, общие резервы, сверка WB. Сканирование физического кода и практическая приемка остаются на этапе 4 |
| Массовый автоматический подбор КИЗов | Частично | Критично: пока выбирает первые доступные коды, при отсутствии подтвержденной партии может брать из общего пула GTIN. Не разделяет уже маркированный товар и маркировку при сборке; до этапа 4 не использовать на реальных заказах |
| Этикетки WB и DataMatrix | Частично | Новые задания печати и отдельное подтверждение печати; DataMatrix проверяется обратным чтением. Размер фиксирован 58×40 мм, настройки принтера не подключены. Требуются проверка полного сценария, повторной печати и физического принтера |
| Передача в доставку и QR поставки | Частично | Журнал передачи и проверки внешних метаданных есть. Новые экран готовности и получение оригинального QR еще не прошли сквозную приемку. Перевод в доставку не равен приемке WB |

Исходные бизнес-данные в новом коде не заполнены фиктивными продавцами, складами,
GTIN или сроками. Фиксированные параметры печати и алгоритм предложения имени —
известные ограничения, не пользовательские настройки.

## Обновление и ручная проверка этапа 0 на Windows

Остановить запущенный Flow (Ctrl+C). Из папки репозитория FBE в PowerShell:

```powershell
git switch feature/fbe-flow-foundation
git pull --ff-only
cd fbe-flow
.\install_flow.bat
$env:FBE_FLOW_DATA_DIR = Join-Path $env:LOCALAPPDATA 'FBE Flow-stage0'
.\start_flow.bat
```

Для этой приемки используется отдельный пустой каталог. Основная база и сохраненные
ключи не меняются. Не добавлять реальные подключения в проверочный каталог.
Если Git сообщает о локальных изменениях или конфликте — не использовать reset/force.

1. Открыть `http://127.0.0.1:8765/health`: ожидается `status: ok`, `worker: running`.
2. Открыть `http://127.0.0.1:8765`: ожидается предложение создать организацию,
   без прежних подключений и заказов.
3. Создать организацию с названием «Проверка этапа 0»: должны открыться рабочее
   пространство, ассортимент, продажи, ЧЗ и настройки, без фиктивных бизнес-записей.
4. Остановить приложение и снова выполнить `start_flow.bat` в том же PowerShell:
   проверочная организация должна сохраниться.
5. Проверить указанный коммит через `git log -1 --oneline` и сверить таблицу выше.
   Подтвердить этап либо сообщить конкретное расхождение.

Переменная каталога действует только в этом PowerShell. После проверки остановить
Flow и закрыть это окно. Возврат к основной базе выполняется отдельно; данный снимок
не рекомендуется для реальной сборки до приемки соответствующих этапов.

Следующий этап только по команде: **«Этап 0 принят. Выполняй этап 1»**.
