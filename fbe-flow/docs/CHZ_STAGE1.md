# Честный Знак: этап 1

Спецификации сверены 01.10.2026:

- [API НК](https://docs.crpt.ru/gismt/API_%D0%9D%D0%9A/), версия 5.68 от 28.09.2026.
- [True API](https://docs.crpt.ru/gismt/True_API/), версия 737.0 от 01.10.2026.

Из True API применяется только авторизация и чтение сведений организации. Этап не отправляет
документы и не реализует регламенты оборота товарных групп. Справочники, идентификаторы,
категории и статусы получаются от источника; ни одна категория/GTIN/компания не зашиты в core.

| Метод | Использование |
| --- | --- |
| True API v3 `GET /auth/key` | Случайная строка и UUID запроса авторизации |
| True API v3 `POST /auth/simpleSignIn` | Присоединенная подпись случайной строки в base64, `inn`, `unitedToken=true` |
| True API v3 `GET /participants?inns=...` | Сведения организации, включая приватные роли и подключенные группы |
| НК `GET /v3/categories` | Дерево категорий |
| НК `GET /v3/etagslist?owner_inn=...&offset=...` | Собственные товары и хеши, максимум 100 на страницу |
| НК `GET /v3/feed-product?good_ids=...` | Полные доступные сведения собственных карточек, до 25 ID с разделителем `;` |
| НК `GET /v3/product?gtin=...` | Отдельный просмотр доступной карточки по GTIN |

НК принимает токен ГИС МТ в `Authorization: Bearer`. Авторизация использует сертификат
текущего пользователя Windows и подписывает исходные UTF-8 байты challenge через CAdESCOM.
Ограниченный кеш учитывает `expireDate`, seller credential reference, ИНН, среду и сертификат.
При 401 кеш сбрасывается, операция показывает ошибку без скрытого повтора.

При подключении проверяются приватные сведения выбранной организации и доступ к методам
НК. Публичные сведения о чужом участнике не считаются подтверждением доступа.
Внешний account ID включает среду и ИНН (`sandbox:ИНН` / `production:ИНН`):
подключения одного ИНН в разных средах не конфликтуют и не смешивают карточки.
Это проверка подключения в локальном приложении, не отдельная многопользовательская авторизация.
Субаккаунтный обзор чужих карточек не заявлен как поддержанный сценарий этапа 1.

Хеши `etagslist` относятся к внешним карточкам. Полученная через `feed-product` версия
может содержать черновик; принудительное чтение предусмотрено отдельно. Идентификаторы
остаются строками с ведущими нулями; совпадение GTIN не объединяет записи разных источников.
Публичный поиск не перезаписывает собственный источник.

Страница нормализованных записей, индекс присутствия, прогресс, успешный статус операции
и следующая страница записываются одной транзакцией. При отсутствии деталей НК сохраняется
индекс карточки с `detail_available=0`, прежняя копия не затирается. Из этого флага нельзя
выводить конкретную причину отказа; интерфейс показывает только подтвержденную недоступность.
После полного обхода отсутствующие записи помечаются `present=0`, физически не удаляются.
Изменение total между страницами и повтор ID в одном обходе приводят к остановке чтения.
Внешний API не предоставляет атомарный снимок; отметка присутствия описывает последний обход.

Таймаут одного HTTP-вызова 20 секунд, лимит ответа 30 МиБ. Redirect не разрешен;
URL, токены, запросы и сырые тексты исключений не записываются в журнал worker.
При 429/5xx чтение прекращается с понятным кодом; пользователь может повторить синхронизацию.
ЧЗ применяет отдельные и общие лимиты API организации; клиент не обещает обход лимитов.

Тесты используют transport/signer/vault doubles по официальным форматам, включая неполные
и ошибочные ответы, а Windows CI проверяет настоящий DPAPI CurrentUser. Для приемки живого
обмена отдельно проверить сертификат/МЧД, роль, доступ к НК и чтение реальных карточек на
пользовательском Windows. Сам факт прохождения CI не подтверждает живой обмен с ЧЗ.
