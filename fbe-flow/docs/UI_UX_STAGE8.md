# FBE Flow 0.8 — рабочий интерфейс

Цель: быстро найти товар или задачу, выполнить действие и увидеть его результат.
Единый ассортимент остается источником GTIN, классификации, документов, партий
и подтверждения нанесения. Обновление интерфейса сохраняет контуры ЧЗ, WB, Ozon и KIT.

## Навигация

| Раздел | Рабочая задача |
| --- | --- |
| Рабочее пространство | Настраиваемая сводка задач, переход к нужным заказам |
| Ассортимент | Товары, документы, партии, внешние связи, XLSX и классификация |
| Продажи | WB/Ozon в переключателе маркетплейсов, отдельный контекст магазина |
| Честный Знак | Коды, оборот, каталог НК, история |
| Настройки | Организации, интеграции, печать, приложение |

На рабочем экране нет версии, статуса worker, формы подключения или постоянной
плашки выбора продавца. Одна организация выбирается автоматически. При нескольких
в шапке появляется компактный переключатель; стартовая страница помнит последний выбор.
Добавление и переименование находятся в настройках. Переключение организации открывает
ее пространство и закрывает прежние диалоги. URL и серверная проверка seller задают
контекст данных каждого действия.

Старые адреса сохранены как перенаправления. Параметры подключения, фильтры и история
сохраняются при переходе. Название интернет-магазина задается в интеграциях и отображается
в продажах; техническое имя адаптера KIT остается прежним.

## Рабочее пространство

Начальный набор: «К сборке», «К отгрузке», «Требует внимания». Дополнительно доступны
сохраненные коды маркировки и документы с истекающим сроком. Пользователь добавляет,
скрывает и переставляет виджеты, выбирает канал, склад и статус. До 12 виджетов,
включая несколько разных фильтров одного вида. Настройки хранятся для организации.

Счетчики используют локальные записи, без случайных чисел и демонстрационных заказов.
Рядом видны примеры заказов, доступный срок, время обновления и состояние синхронизации.
Необновленный пустой канал показывает «—» и предлагает обновление. Старые, неполные
и ошибочные результаты обозначены отдельно. Обновление экрана только читает SQLite;
запрос к площадке запускается отдельной кнопкой. Активное обновление блокирует повторный запуск.

| Виджет | Используемые сохраненные данные |
| --- | --- |
| К сборке | WB FBS new/confirm, Ozon awaiting_packaging, KIT NEW/ORDER_PLACED/WAIT_FOR_CONFIRMATION |
| К отгрузке | Открытые поставки WB, Ozon awaiting_deliver, KIT WAIT_FOR_DELIVERY |
| Требует внимания | Неопределенные/частичные/отклоненные действия, ручной шаг KIT, последние неудавшиеся задачи, карточки без связей |
| Коды маркировки | Количество сохраненных КМ по GTIN и внешнему статусу |
| Документы | Документы с истекшим сроком или сроком в ближайшие 30 дней |

Открытая поставка WB не подтверждает физическую готовность к отгрузке. Счетчик КМ
не обещает свободный резерв или допустимость назначения: эти проверки выполняются
при действии. Срок документа не подменяет проверку реестра. Повторное успешное задание
того же подключения/операции/области исключает предыдущую ошибку из сводки.

Переход из виджета открывает тот же канал, подключение, этап, статус и склад.
Поиск и страница сбрасываются, чтобы сохраненный ранее фильтр не скрывал показанные задачи.
Журнал проблем открывается для соответствующего аккаунта.

## Настройки

| Вкладка | Содержимое |
| --- | --- |
| Организации | Список, добавление, название, юридическое наименование, ИНН |
| Интеграции | Подключение WB/Ozon/KIT/ЧЗ, проверка доступа, смена ключа, УКЭП/True API, параметры СУЗ, название магазина |
| Печать | Размер этикетки в мм, отдельная пробная этикетка |
| Приложение | Имя оператора, плотность таблиц, период обновления экрана, резервная копия, диагностика |

Проверка доступа получает идентичность аккаунта и не отправляет документы или заказы.
Смена реквизитов организации не перепривязывает подключение: внешний аккаунт и ИНН
проверяются прежними интеграционными правилами. Поля секретов пустые, с типом password;
сохраненные токены не выводятся. JSON дополнительных адаптеров и диагностика свернуты.

Копия через sqlite3.backup содержит всю локальную базу: организации, каталоги, журналы
и вложения документов. Ключи DPAPI хранятся отдельно и в копию SQLite не входят.
Имя файла копии проверяется, произвольный путь загрузить нельзя.

В Flow нет нативного драйвера принтера. Пробная этикетка использует системный диалог
браузера: принтер выбирается там, масштаб — 100%. Она не содержит реального КМ,
не добавляет printed/applied и не является печатью DataMatrix. Экспорт КМ и журнал
оператора остаются прежними; этот этап не обещает аппаратную печать или тихую отправку.

## Операционные экраны

Фильтры, страница и подключение продаж сохраняются в пределах вкладки браузера
отдельно по организации и каналу. Явный URL имеет приоритет. Автообновление сохраняет
поиск, выбор, открытый диалог и прокрутку; измененный статус WB исключает непригодное
задание из видимого выбора. Панель пакетных действий WB появляется при выборе заданий.
Детали задания содержат понятные поля; исходные атрибуты раскрываются отдельно.

Перед внешним действием показаны организация, аккаунт и проверенный ИНН.
Подготовка, отправка, прием запроса, подтверждение, неопределенный результат и сверка
сохраняют прежнюю семантику. История действий находится в рабочем разделе, общие фоновые
операции — в боковой панели «Задачи». Передача КМ WB и глобальный резерв не изменены.

В ассортименте сразу доступны основные поля и классификация. Габариты, упаковка,
описание и состав раскрываются группами. Документы, партии, XLSX и связи сохранены.
В ЧЗ выбор товара из ассортимента подставляет GTIN и известную группу в рабочие формы.
ID шаблона СУЗ и специальные атрибуты берутся из своей группы; JSON для документов
со специальной структурой остается доступным. Выбор товара не доказывает его готовность
к эмиссии или обороту, проверки НК/ЧЗ продолжают выполняться сервером.

## Правила оформления и приемки

- Один заголовок страницы, компактная постоянная навигация, основной акцент на действиях.
- Таблицы для сравнения записей, раскрываемые детали для технических данных.
- Подписи полей, видимый фокус, управление вкладками стрелками/Home/End, переход к содержимому.
- На мобильной ширине меню раскрывается кнопкой, элементы управления имеют минимум 44 px,
  широкая таблица прокручивается в своем контейнере.
- Нельзя объявлять отправку подтверждением площадки или локальное событие фактом оборота ЧЗ.
- Без автоматических внешних записей при открытии страницы, смене организации или обновлении экрана.

Схема SQLite остается v7; preferences сохраняются в settings. UUID товаров, связи,
подключения, очередь, миграции 001–007 и контуры отправки не переписываются.

Проверки: Python/HTTP сценарии изоляции, сохранения настроек, совпадения счетчиков
с фильтрами, переименования, копии БД и отсутствия побочных действий пробной печати;
прежние интеграционные сценарии. `qa/catalog_browser.cjs` проверяет ассортимент/XLSX,
`qa/workspace_browser.cjs` — виджеты, продажи, настройки, ЧЗ, мобильную навигацию
и смену организации. GitHub Actions запускает их в одном Linux job и сохраняет снимки.
Проверка настоящих кабинетов, сертификата Windows и физического принтера выполняется владельцем.
