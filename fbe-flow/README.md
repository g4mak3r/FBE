# FBE Flow

Локальная операционная платформа для продавцов маркетплейсов. Версия 0.2:
Foundation + Честный Знак, этап 1 (чтение Национального каталога).

Python 3.11+, FastAPI, SQLite, Jinja2, vanilla JavaScript. Независимый проект в `fbe-flow/`.

## Запуск и обновление на Windows

Установить Python 3.11 или новее. Открыть каталог `fbe-flow`, запустить
`install_flow.bat`, затем `start_flow.bat`. Открыть <http://127.0.0.1:8765>.
Остановка: Ctrl+C в окне запуска. Для обновления сначала остановить старую версию,
скачать актуальную ветку и повторить `install_flow.bat` в новой папке `fbe-flow`.
Данные остаются в прежней папке. При обновлении базы v2 до v3 автоматически создается
`flow.before-v3.sqlite3`; migrations 001 и 002 не менялись.

Или из PowerShell:

```powershell
cd fbe-flow
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -c requirements-lock.txt .
.\.venv\Scripts\python.exe -m fbe_flow
```

## Честный Знак: подключение и просмотр

1. Создать продавца или выбрать существующего в боковой панели.
2. Открыть «Честный Знак». Указать название подключения, среду и ИНН организации.
   Тестовая и промышленная среды используют разные аккаунты и токены.
3. Для входа по УКЭП нужны установленный КриптоПро CSP, компоненты CAdESCOM
   и действующий сертификат с закрытым ключом в хранилище текущего пользователя Windows.
   Нажать «Найти сертификаты УКЭП» и выбрать сертификат организации или уполномоченного лица
   с действующей МЧД. Носитель ключа должен быть доступен для подписи запроса авторизации.
   Альтернативный временный вариант — действующий токен True API (UUID или JWT).
   API KEY Национального каталога в поле токена не подходит.
4. Нажать «Проверить и подключить». Flow проверит сведения организации и доступ
   к НК, затем загрузит данные аккаунта и дерево категорий в фоновом задании.
5. Нажать «Синхронизировать». В таблице появятся собственные карточки аккаунта,
   включая черновики и опубликованные карточки, доступные через `feed-product`.
   Видны GTIN, категория, статусы НК, флаги возможности эмиссии и ввода в оборот.
   Нажатие на название открывает полученные атрибуты и исходные данные карточки.
6. Поиск фильтрует локальные карточки по названию, GTIN или ID НК.
   «Запросить НК» получает доступные данные карточки по GTIN отдельно: этот результат
   не утверждает принадлежность аккаунту и не заменяет собственную карточку.

Повторная синхронизация сравнивает хеши и загружает изменившиеся карточки.
«Перезагрузить все карточки» принудительно обновляет детали, включая неподписанные правки,
которые могут не отражаться в хеше опубликованной версии. Синхронизация запускается вручную;
worker продолжает чтение с закрытым браузером. Очередь следующей страницы хранится в SQLite.
После аварии текущая страница помечается как прерванная: запустить синхронизацию заново.

Исчезнувшие из последней полной выдачи карточки остаются в локальной копии с отметкой.
Если НК не вернул детали карточки (например, статус «Требует обработки»), строка остается
видимой с пометкой; прежние данные сохраняются и могут быть устаревшими. Полный обход
не означает, что детали всех карточек доступны. Время последнего полного обхода показано отдельно.
При изменении количества товаров между страницами обход останавливается; его можно повторить.
API НК не обещает атомарный снимок каталога. Flow не удаляет записи по неполному чтению.

Ошибка `http_401`: обновить доступ в интерфейсе или проверить УКЭП.
`http_403`: проверить права организации/пользователя в ЧЗ.
`http_429`: дождаться восстановления лимита НК, затем повторить чтение.
Нет автоматических повторов запросов. При обновлении доступа нужно дождаться конца очереди
этого подключения. Токены хранятся отдельно от БД, защищены Windows DPAPI CurrentUser;
их нельзя перенести на другого пользователя/компьютер простым копированием папки.
Для просмотра уже загруженной копии интернет и носитель УКЭП не требуются.

Этап 1 использует только методы чтения и запрос авторизации. Редактирование,
публикация/подписание карточек, СУЗ, заказ кодов, ввод/вывод из оборота еще не реализованы.
Обмен с реальным аккаунтом и физическим носителем УКЭП требует отдельной проверки на Windows;
автоматические тесты используют изолированные ответы по официальным форматам.

## Разработка и проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -c requirements-lock.txt -e ".[dev]"
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
```

На Linux/macOS: `python3 -m venv .venv`, затем те же команды через `.venv/bin/python`.
Локальный каталог и Foundation работают на этих ОС; реальное хранение ключей ЧЗ
через DPAPI и вход по КриптоПро доступны на Windows. Plaintext fallback нет.
CI проверяет Ubuntu (Python 3.11) и Windows (Python 3.12); тест DPAPI выполняется на Windows.
Компоненты КриптоПро и реальная УКЭП не входят в CI.

Зависимости проекта закреплены в `pyproject.toml`, транзитивные версии — в `requirements-lock.txt`.

## Данные и API

Windows: `%LOCALAPPDATA%\FBE Flow\flow.sqlite3`. Linux/macOS:
`$XDG_DATA_HOME/fbe-flow/flow.sqlite3` или `~/.local/share/fbe-flow/flow.sqlite3`.
Можно указать `FBE_FLOW_DATA_DIR` или запустить
`python -m fbe_flow --data-dir C:\FBEFlowData --port 8765`.
Данные не зависят от каталога установки и не попадают в Git.
Для копирования/резервирования всей папки данных сначала остановить приложение.

Один процесс на папку данных; несколько workers не поддерживаются.
Shell работает без CDN. OpenAPI: `/openapi.json`; необязательные `/docs` и `/redoc`
используют CDN FastAPI и могут требовать интернет.

API подключений, настроек, операций и нормализованных записей:
`/api/sellers/{seller_id}/...`. Контур НК: `/api/sellers/{seller_id}/marking/...`.
Запуск обхода: `POST /marking/{connection_id}/sync` с `{"force": false}`;
пагинация и run ID определяются сервером. Не запускать `nk.sync` через generic operation route.
Локальные изменяющие запросы требуют JSON и заголовок `X-FBE-Flow: 1`.
Ошибки: `404` неизвестный/чужой ID, `409` конфликт, `422` некорректные данные,
`502` ошибка чтения внешнего API. Credentials не сохранять в settings/config/payload.

## Структура

| Путь | Назначение |
| --- | --- |
| `src/fbe_flow/core/` | БД, миграции, модели, контракт integrations, защищенное хранилище ключей |
| `src/fbe_flow/modules/` | Sellers, connections, records, operations, settings и локальный контур НК |
| `src/fbe_flow/integrations/chz/` | HTTP API НК/True API, авторизация и мост к КриптоПро |
| `src/fbe_flow/web/` | Routes, Jinja templates, CSS и vanilla JS |
| `src/fbe_flow/app.py`, `__main__.py` | Сборка приложения и локальный CLI |
| `tests/` | Isolation, FK, транзакции, очередь, миграции, HTTP, НК и Windows DPAPI |
| `ARCHITECTURE.md` | Архитектурная основа следующих этапов |
| `docs/CHZ_STAGE1.md` | Проверенные официальные методы и границы этапа 1 |
