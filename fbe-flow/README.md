# FBE Flow

Локальная операционная платформа для продавцов. Версия 0.6:
Foundation + Честный Знак (этапы 1–3) + Wildberries FBS (этап 4) + Ozon FBS (этап 5)
и отдельный интернет-магазин на Яндекс KIT (этап 6).
В блоке «Маркетплейсы» переключаются WB/Ozon; блок магазина можно назвать своим именем.
НК, СУЗ и ввод в оборот связаны с позициями заказов. Резерв физического КМ общий для каналов.

Python 3.11+, FastAPI, SQLite, Jinja2, vanilla JavaScript. Независимый проект в `fbe-flow/`.

## Запуск и обновление на Windows

Установить Python 3.11 или новее. Открыть каталог `fbe-flow`, запустить
`install_flow.bat`, затем `start_flow.bat`. Открыть <http://127.0.0.1:8765>.
Остановка: Ctrl+C в окне запуска. Для обновления сначала остановить старую версию,
скачать актуальную ветку и повторить `install_flow.bat` в новой папке `fbe-flow`.
Данные остаются в прежней папке. При обновлении существующей базы до v6 автоматически
создается `flow.before-v6.sqlite3`; migrations 001–005 не менялись. Прежние подключения,
UUID карточек, очередь и защищенные ключи сохраняются.

Или из PowerShell:

```powershell
cd fbe-flow
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -c requirements-lock.txt .
.\.venv\Scripts\python.exe -m fbe_flow
```

## Честный Знак: подключение и просмотр

1. Создать продавца или выбрать существующего в боковой панели.
2. Открыть «Честный Знак». Указать название подключения, среду и ИНН организации.
   Тестовая и промышленная среды используют разные аккаунты и токены.
3. Для входа по УКЭП нужны установленный КриптоПро CSP, компоненты CAdESCOM
   и действующий сертификат с закрытым ключом в хранилище текущего пользователя Windows.
   Нажать «Найти сертификаты УКЭП» и выбрать сертификат организации или уполномоченного лица
   с действующей МЧД. Носитель ключа должен быть доступен для подписи запроса авторизации.
   Альтернативный временный вариант — действующий токен True API (UUID или JWT).
   API KEY Национального каталога в поле токена не подходит.
4. Нажать «Проверить и подключить». Flow проверит сведения организации и доступ
   к НК, затем загрузит данные аккаунта и дерево категорий в фоновом задании.
5. Нажать «Синхронизировать». В таблице появятся собственные карточки аккаунта,
   включая черновики и опубликованные карточки, доступные через `feed-product`.
   Видны GTIN, категория, статусы НК, флаги возможности эмиссии и ввода в оборот.
   Нажатие на название открывает полученные атрибуты и исходные данные карточки.
6. Поиск фильтрует локальные карточки по названию, GTIN или ID НК.
   «Запросить НК» получает доступные данные карточки по GTIN отдельно: этот результат
   не утверждает принадлежность аккаунту и не заменяет собственную карточку.

Повторная синхронизация сравнивает хеши и загружает изменившиеся карточки.
«Перезагрузить все карточки» принудительно обновляет детали, включая неподписанные правки,
которые могут не отражаться в хеше опубликованной версии. Синхронизация запускается вручную;
worker продолжает чтение с закрытым браузером. Очередь следующей страницы хранится в SQLite.
После аварии текущая страница помечается как прерванная: запустить синхронизацию заново.

Исчезнувшие из последней полной выдачи карточки остаются в локальной копии с отметкой.
Если НК не вернул детали карточки (например, статус «Требует обработки»), строка остается
видимой с пометкой; прежние данные сохраняются и могут быть устаревшими. Полный обход
не означает, что детали всех карточек доступны. Время последнего полного обхода показано отдельно.
При изменении количества товаров между страницами обход останавливается; его можно повторить.
API НК не обещает атомарный снимок каталога. Flow не удаляет записи по неполному чтению.

Ошибка `http_401`: обновить доступ в интерфейсе или проверить УКЭП.
`http_403`: проверить права организации/пользователя в ЧЗ.
`http_429`: дождаться восстановления лимита НК, затем повторить чтение.
Нет автоматических повторов отправки или выдачи новых КМ. При обновлении доступа нужно дождаться конца очереди
этого подключения. Токены хранятся отдельно от БД, защищены Windows DPAPI CurrentUser;
их нельзя перенести на другого пользователя/компьютер простым копированием папки.
Для просмотра уже загруженной копии интернет и носитель УКЭП не требуются.

## Честный Знак: правки, коды и оборот

1. Выбрать собственные карточки, открыть «Массовое изменение атрибутов» и загрузить
   их общий атрибутивный состав. Атрибуты, типы и допустимые значения берутся из НК.
   Подготовить одно значение или массив правок/удалений; проверить таблицу «Было / Будет».
   Отдельной кнопкой отправить изменения. До отправки Flow заново проверяет карточки.
2. Для публикации выбрать до 10 карточек и подготовить подписание. Flow получает XML
   из НК, показывает состав запроса и подписывает точные UTF-8 байты каждого XML.
   Если содержимое изменилось после подготовки, отправка останавливается.
3. В «Подключение СУЗ» указать OMS ID и omsConnection из своего аккаунта. Нужна УКЭП.
   Выбрать подключенную товарную группу, указать уникальный номер задания, позиции заказа
   и атрибуты своей группы. templateId и cisType заполнить по действующей спецификации группы.
   После подготовки и подписи заказ получает внешний ID; обработка проверяется отдельно.
4. Для готового буфера указать ID заказа, GTIN и количество. Подготовка читает статус
   и список прежних блоков; «Получить новый блок КМ» выполняет одну выдачу и сохраняет
   полный ответ в SQLite. «Скачать блок JSON» возвращает order_id, gtin, block_id и массив
   `codes` с исходными полными КМ; разделитель GS сохраняется как `\u001d` в JSON.
5. Выбрать сохраненные коды и подготовить отчёт о нанесении либо загрузить тело отчёта JSON
   с полными КМ. Flow проверяет принадлежность и статус `EMITTED` перед подписью.
   Успешное нанесение подтверждается статусом отчёта `SUCCESS`, а не фактом отправки.
6. Для ввода в оборот производства РФ или вывода выбрать КИ, создать основу JSON,
   заполнить сведения своей товарной группы и подготовить документ. Перед отправкой
   повторно проверяются ИНН владельца, группа, тип упаковки и статусы `APPLIED` / `INTRODUCED`.
   Документы подписываются и отправляются через True API; итог проверяется по внешнему ID.
7. Журнал хранит отдельные состояния подготовки, отправки, приёма, обработки, частичного
   результата и завершения. Принятые документы проверяются worker даже при закрытой странице.
   Квитанции СУЗ и статусы кодов можно прочитать отдельными действиями.

После потери ответа или перезапуска во время отправки результат помечается неизвестным;
повторная отправка заблокирована. Для заказа/отчёта СУЗ указать внешний ID: Flow сверяет
владельца, время, квитанцию и исходное содержимое. Для кодов указать ID нового блока:
чтение `codes/retry` восстанавливает ранее выданные КМ без новой выдачи. Для True API
сверяются тип, ИНН, группа и точное содержимое. Для НК проверяются текущие данные карточек.
При нескольких подходящих новых блоках автоматическое сопоставление запрещено.
Повтор после подтвержденного отказа до приёма запроса доступен отдельным действием.

Поддержанный оборот: JSON-документы `LP_INTRODUCE_GOODS` и `LK_RECEIPT` для единиц товара
с GS1 КИ `01 + GTIN-14 + 21 + serial`. Агрегация, другие типы документов и форматы кодов,
CSV/XML-документы оборота и печать этикеток не входят в этот контур. Атрибуты и условия
отдельных товарных групп окончательно проверяет ЧЗ. Подробности: [docs/CHZ_WORKFLOWS.md](docs/CHZ_WORKFLOWS.md).

Обмен с реальным аккаунтом и физическим носителем УКЭП требует проверки на пользовательском
Windows; автоматические тесты используют изолированные ответы по официальным форматам.

## Wildberries FBS и передача кодов ЧЗ

1. Открыть «Маркетплейсы → WB», подключить API-токен категорий «Контент» и «Маркетплейс».
   WB подтверждает продавца и ИНН. Токен только на чтение позволяет синхронизацию;
   для команд нужен доступ на запись. Токен хранится в защищенном хранилище Windows.
2. Синхронизировать товары, склады, поставки и задания. Задания загружаются за 30 дней
   и отдельно из выдачи новых. Показаны состояния WB и время обновления локальной копии.
3. В «Товары» связать размер chrtID с собственной карточкой НК, GTIN и группой
   производственного аккаунта ЧЗ с тем же ИНН. В «Задания» назначить сохраненные полные КМ.
4. Проверить состав и отправить коды. Перед отправкой ЧЗ заново подтверждает ввод в оборот,
   владельца и соответствие товара. Полный КМ с GS передается в WB; успешный HTTP-ответ
   и последующее подтверждение метаданных показаны отдельно. Другие коды не перезаписываются.
5. Создать поставку, добавить или переместить совместимые задания, проверить живой состав
   и передать в доставку после подтверждения метаданных. Пустую активную поставку можно удалить.
6. При потере ответа открыть журнал и сверить результат с WB. Приложение сохраняет
   принятые и частичные результаты и не повторяет запись автоматически. Печать и статус
   кода в ЧЗ остаются отдельными; передача в WB не выполняет вывод из оборота.

Подробности, методы и восстановление: [docs/WB_STAGE4.md](docs/WB_STAGE4.md).
Промышленный обмен WB/ЧЗ требует приемки на действующем аккаунте продавца.

## Ozon FBS: этап 5

1. В «Маркетплейсы» выбрать Ozon, ввести Client-Id и API-ключ Ozon Seller.
   Проверяются доступ и ИНН организации. Обновить товары, склады, отправления,
   существующие отгрузки и возвраты. Отправления читаются за последние 30 дней.
2. Связать товар со своей карточкой НК. ID карточки Ozon и SKU отправления различаются:
   Flow сохраняет оба и назначает коды конкретному SKU и экземпляру товара.
3. Открыть заказ, назначить полный КМ на каждую единицу позиции. ЧЗ проверяется заново.
   Запрос Ozon сначала принимается, затем проверка каждого экземпляра подтверждает КМ.
4. Подготовить сборку после подтверждения всех маркируемых позиций. Отправление переходит
   в готовность к отгрузке; доставка покупателю читается отдельным статусом.

Потерянный ответ сверяется чтением без повторной записи. FBO и создание/закрытие отгрузок
Ozon в этот этап не входят. Подробности: [docs/COMMERCE_STAGES5_6.md](docs/COMMERCE_STAGES5_6.md).

## Интернет-магазин на Яндекс KIT: этап 6

1. Открыть «Интернет-магазин → Название блока магазина», сохранить свое название.
   Оно изменит заголовок и пункт меню только для выбранного продавца.
2. Подключить токен из «Настройки → API» кабинета KIT и указать ИНН организации для ЧЗ.
   KIT подтверждает ID магазина; ИНН не возвращается этим API и остается заявленным вами.
3. Обновить варианты товаров, склады и все страницы заказов. Фильтр статуса и поиск
   работают по локальным данным; полнота чтения показана явно. Заказ сохраняет оплату,
   суммы, отказы и собственную доставку каждого грузоместа.
4. Связать маркируемый вариант с НК, зарезервировать КМ и проверить ЧЗ. Скопировать полные
   коды и внести их в заказ в кабинете KIT: публичного метода записи КМ нет.
   Для одной единицы точный `truthful_label` подтверждается повторным чтением.
   Формат нескольких КМ в этом строковом поле не документирован; такие позиции и
   последующее подтверждение/завершение маркированного заказа обрабатываются в кабинете.
5. Подтвердить подготовленный заказ; завершить собственную доставку или самовывоз
   отдельным действием. Доставку Яндекс Доставки, CDEK и других служб завершает сама служба.
   Цены и абсолютные остатки доступны через подготовку, проверку и журнал.

Платежный провайдер не зашит в Flow. Оплата/чеки и разрешительный режим обслуживаются
подключенными в KIT системами; Flow не создает повторный чек или вывод КМ из оборота.
Возврат и частичный выкуп оформляются в кабинете KIT, отдельно от отмены заказа.

## Разработка и проверки

```powershell
.\.venv\Scripts\python.exe -m pip install -c requirements-lock.txt -e ".[dev]"
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m ruff format --check .
```

На Linux/macOS: `python3 -m venv .venv`, затем те же команды через `.venv/bin/python`.
Локальный каталог и Foundation работают на этих ОС; реальное хранение ключей ЧЗ
через DPAPI и вход по КриптоПро доступны на Windows. Plaintext fallback нет.
CI проверяет Ubuntu (Python 3.11) и Windows (Python 3.12); тест DPAPI выполняется на Windows.
Компоненты КриптоПро и реальная УКЭП не входят в CI.

Зависимости проекта закреплены в `pyproject.toml`, транзитивные версии — в `requirements-lock.txt`.

## Данные и API

Windows: `%LOCALAPPDATA%\FBE Flow\flow.sqlite3`. Linux/macOS:
`$XDG_DATA_HOME/fbe-flow/flow.sqlite3` или `~/.local/share/fbe-flow/flow.sqlite3`.
Можно указать `FBE_FLOW_DATA_DIR` или запустить
`python -m fbe_flow --data-dir C:\FBEFlowData --port 8765`.
Данные не зависят от каталога установки и не попадают в Git.
Для копирования/резервирования всей папки данных сначала остановить приложение.

Один процесс на папку данных; несколько workers не поддерживаются.
Shell работает без CDN. OpenAPI: `/openapi.json`; необязательные `/docs` и `/redoc`
используют CDN FastAPI и могут требовать интернет.

API подключений, настроек, операций и нормализованных записей:
`/api/sellers/{seller_id}/...`. Контур ЧЗ: `/api/sellers/{seller_id}/marking/...`;
WB: `/api/sellers/{seller_id}/wb/...`; Ozon/KIT: `/api/sellers/{seller_id}/commerce/...`.
Запуск обхода: `POST /marking/{connection_id}/sync` с `{"force": false}`;
пагинация и run ID определяются сервером. Не запускать `nk.sync` через generic operation route.
Локальные изменяющие запросы требуют JSON и заголовок `X-FBE-Flow: 1`.
Ошибки: `404` неизвестный/чужой ID, `409` конфликт, `422` некорректные данные,
`502` ошибка чтения внешнего API. Credentials не сохранять в settings/config/payload.
